# Phase 1 Plan 02: Core Pydantic Data Schemas, FastAPI Contract, and Validation Smoke Tests

## Objective

- **What:** Implement the unified Pydantic domain schemas (`ProvenanceEnum`, `TriageClassEnum`, `PhysicalCellId`, `TelemetryFrame`, `RelaxationTelemetry`, `BatteryPulseTelemetry`, `DiagnosticPrediction`), a minimal FastAPI application entrypoint with typed `GET /` and `GET /health` contracts, and a comprehensive pytest smoke test suite covering schemas and API endpoints.
- **Why:** Delivers ARCH-03 and the foundational API interface, locking down deep immutability, exact timestamp cadence, probability distributions, provenance integrity, and physical cell identity boundaries before any computation, ML training, or simulation code is written.
- **Output:** `schemas_provenance.py`, `schemas_battery.py`, `backend/app/main.py`, `backend/tests/test_schemas.py`, and `backend/tests/test_api.py`.

<task type="code">
  <name>Task 2: Battery Telemetry and Diagnostic Prediction Schemas (ARCH-03)</name>
  <files>backend/app/models/schemas_battery.py</files>
  <action>
    Implement `backend/app/models/schemas_battery.py` adhering strictly to ARCHITECTURE.md specifications:
    1. `TelemetryFrame`: Single 100ms hardware frame with `cell_id: PhysicalCellId`, `cycle_index: Optional[int]`, `timestamp: float >= 0.0`, `voltage: float in [0.0, 5.0]`, `current: float in [0.0, 10.0]`, `bulk_temperature: float`, `thermal_frame_8x8: List[List[float]]` (validated exactly 8x8 with finite values), and `provenance: ProvenanceEnum`.
    2. `RelaxationTelemetry`: 2-second post-pulse relaxation period with `duration_s == 2.0`, exactly 20 samples at 10Hz covering `[10.0, 11.9]s` with strict monotonicity and exact spacing: `abs(timestamps[i] - round(10.0 + 0.1 * i, 1)) <= 1e-4`, finite float checks on `voltage` (20 floats) and `bulk_temperature` (20 floats).
    3. `BatteryPulseTelemetry`: 10-second active discharge pulse payload:
       - `cell_id: PhysicalCellId`, `cycle_index: Optional[int]`, `provenance: ProvenanceEnum`, `v_pre_pulse: float in [0.0, 5.0]` (finite float).
       - `sampling_rate_hz == 10.0`, `duration_s == 10.0`.
       - Exactly 100 active pulse samples at 10Hz covering `[0.0, 0.1, 0.2, ..., 9.9]s`.
       - Timestamps must be strictly increasing (`timestamps[i] > timestamps[i - 1]` for $i \ge 1$) and approximately 0.1s apart within explicit tolerance: `abs(timestamps[i] - round(i * 0.1, 1)) <= 1e-4`.
       - Reject duplicate timestamps, out-of-order timestamps, incorrect cadence, and invalid sample counts (!= 100).
       - Maintain established timing convention: active pulse = 100 samples from 0.0 to 9.9s, pulse boundary/end = 10.0s, relaxation = 10.0 to 11.9s.
       - Fixed 3.0A discharge current contract: each sample in `current` must satisfy `abs(c - 3.0) <= 0.05` (within `[2.95, 3.05]A`).
       - `voltage` and `bulk_temperature` exactly 100 finite float samples.
       - `thermal_frames`: exactly 100 frames, each strictly 8x8 of finite floats.
       - `relaxation: RelaxationTelemetry`: mandatory 2-second relaxation payload.
    4. `DiagnosticPrediction`: Frozen model enforcing deep immutability:
       - `cell_id: PhysicalCellId`, `cycle_index: Optional[int]`.
       - `provenance: Literal[ProvenanceEnum.PREDICTED] = ProvenanceEnum.PREDICTED` (rejecting REAL or SYNTHETIC).
       - `triage_class: TriageClassEnum` (one of `REUSE`, `RETIRE`, `INVESTIGATE`).
       - `class_probabilities`: must contain EXACTLY the three keys `{"REUSE", "RETIRE", "INVESTIGATE"}`. Reject missing keys, extra keys, and unknown keys. Every probability must be in `[0.0, 1.0]`. Sum of probabilities must equal `1.0` within tolerance: `abs(sum - 1.0) <= 1e-4`.
       - `confidence: float in [0.0, 1.0]`: must match the selected class probability within canonical tolerance: `abs(confidence - class_probabilities[triage_class.value]) <= 1e-4`. Strict floating-point equality is prohibited.
       - `extracted_features`: canonical 14 extracted diagnostic features.
       - `recommendation: str`: actionable diagnostic recommendation text.
       - **Deep Immutability Invariant**: Nested `class_probabilities` and `extracted_features` structures must be deeply immutable, not merely protected by shallow `ConfigDict(frozen=True)`. Callers can read probability and feature values normally (via standard key lookup, iteration, and `.get()`), but in-place mutations of nested mappings post-construction must raise an error (e.g. `TypeError`). Existing validation semantics remain intact.
  </action>
  <verify>Import `schemas_battery` and verify that models accept compliant payloads while rejecting invalid keys, invalid timestamp cadence, current out-of-bounds, probability sum mismatch, and in-place nested mutations.</verify>
  <done>Telemetry and prediction schemas implemented with all validation invariants, exact timestamp cadence, and deep immutability.</done>
</task>
